# PoE → p9 设计参考笔记

本文件回答三件事：PoE 的哪些机制值得 p9 借鉴、哪些不要碰、p9 应该用哪些具体参数起步。
所有数字来自 `data/*.json`（快照 2026-10-19，见 `README.md`），括号内为文件与字段。
**所有名称、文本、美术均为 GGG 专有内容，p9 不复制；下文的数值只用于校准量级。**

## 0. 结论

PoE 的装备系统本质上是三件事的乘积：**基底数值（随 ilvl 成长）× 词缀 tier（离散阶梯）
× 稀有度/掉落约束（获取难度）**。p9 值得照搬的是这套**结构**和它的**参数形状**；
不值得照搬的是它的**规模**（123 个后缀/槽、6 条词缀/件、1000+ 天赋点、交易+赛季经济）。

p9 的目标应是：每条词缀都能被玩家记住，每件黄装都有 2–3 条“看得懂的选择”，
而不是“在 123 个后缀里抽 3 个”。

## 1. 适合 p9 的机制

### 1.1 基底 / 槽位 / 物品等级

- **结构**：基底决定槽位、背包尺寸、需求属性、基础防御/武器伤害；掉落时带一个 `ilvl`，
  只有 `required_level <= ilvl` 的词缀 tier 才能出现。这是 p9 最该保留的“进度闸门”。
- **证据**：1072 个已发布装备基底，573 个带 1 条固定词缀；25 个物品类别（`data/base-types.json`）。
  各槽位词缀池随 ilvl 单调增长：ring 前缀 4（ilvl 1）→ 78（ilvl 83），后缀 12 → 123；
  body armour 前缀 4 → 43，boots 4 → 38（`data/drops.json.affix_pool_by_ilvl`）。
- **成长形状**（拟合 `y = a·ilvl^b`，`data/base-types.json.scaling_fits`）：
  - 胸甲护甲 `12.7 · ilvl^0.89`（r²=0.84），闪避 `11.3 · ilvl^0.92`，能量护盾 `3.9 · ilvl^0.80`
  - 单手剑物理 DPS `8.8 · ilvl^0.51`（r²=0.91），双手斧 `5.7 · ilvl^0.77`，弓 `8.8 · ilvl^0.53`
  - 属性需求 `≈ 4.3 · ilvl^0.82`
  - 解读：**防御近似线性**，武器 DPS 近似平方根；双手武器成长快于单手，用来补偿攻速。
    p9 若不做攻速差异，可把武器统一成 `ilvl^0.65` 左右，避免单手武器后期乏力。
- **建议**：p9 保留 ilvl 概念但压缩到 1–80；每个基底一条固定词缀（implicit）即可，
  不要做 PoE 的“基底专属 implicit 池 + 附魔 + 腐化 implicit”三层。

### 1.2 词缀族（family）→ tier → 权重

这是 PoE 数据里最值得 p9 直接借用的抽象：

- **族**：同一“语义”的词缀互斥（PoE 的 mod group）。`data/affixes.json` 用
  `kind + 主 stat + 可用槽位集合` 归一化出 **203 个族 / 916 个 tier**。
- **tier**：族内按等级需求排序，tier 1 = 最低需求。中位每族 4 个 tier（p25=2，p75=7，最大 12）；
  48 个族只有 1 个 tier（多为后期特殊词缀，p9 不需要）。
- **权重**：同一 tier 在不同槽位有不同权重（ring 常见、body armour 稀少），且
  “权重 0”用来做排除。p9 应保留 `slot → weight` 的稀疏表，而不是布尔“能不能出”。
- **经典阶梯**（可直接借鉴形状）：
  - 生命前缀 8 tier：ilvl 1/5/11/18/24/30/36/44，掷值 `3-9` → `100-114`，
    **每 tier 上限 +15**，8 个 tier 总倍率 12.7×（`prefix.life_flat.073`）。
  - 火抗后缀 8 tier：ilvl 1/12/24/36/48/60/72/84，`6-11` → `46-48`，
    总倍率 4.36×，但**最后一级只多 2 点上限**（46-48 vs 42-45）——因为 75% 抗性上限把它顶死了。
    p9 要么降低 cap，要么让顶层 tier 改给“最大抗/穿透”而不是继续堆数值。
- **顶级 tier 的实际概率**：PoE 的 tier 权重多为同值（1000），因此顶级概率 ≈ 1/可用 tier 数。
  ring@ilvl83 的 32 个多 tier 族里，顶级 tier 概率中位数 **16.7%**，范围 9.1%–33.3%
  （`data/drops.json.top_tier_probability_ring_ilvl83`）。也就是说 PoE 的“毕业词缀”
  并不稀有，稀有在**池子大 + 每件 6 条 + 交易筛选**。p9 池子小，必须靠权重压顶级概率，
  否则一周就毕业。

### 1.3 数值聚合：基底 → 加法 → 乘法

`data/stats.json.aggregation_model` 给出可执行顺序，p9 直接照这个管线写：

```
base      = base_type_value(ilvl)
flat      = base + Σ flat_adds          # local flat 已折进 base
increased = 1 + Σ increased_pct / 100   # 所有 increased 同层相加
more      = Π (1 + more_pct / 100)      # 每条 more 独立相乘
final     = floor(flat * increased * more + 0.5)
```

- **local vs global**：PoE 的 `local_*` 只作用于物品自身基底，且**每次从基底重算**，不会
  和全局 increased 混进一个池。这是防止“装备二次放大”的关键；p9 若省掉 local 层，
  武器/护甲词缀会指数膨胀。
- **证据**：23346 个 stat id 中，local 类与 aliased（左右手不同键）是独立字段
  （`stats.json` 的 `is_local`/`is_aliased`）；115 个归一化键里有 15 个 local 键。
- **速率类**用 `rate = 1000 / attack_time_ms`，百分比乘在速率上，避免攻速出现“除以零”或
  非线性叠乘；PoE 的 `attack_speed_+%` 与 `cast_speed_+%` 就是两条独立通道。
- **抗性**先加 flat、再 clamp 到 cap；`max_resistance` 提高 cap 本身，而不是加抗性值。
  这是 p9 做“抗性上限”装备词缀的唯一正确顺序。

### 1.4 技能宝石：标签门控 + 等级曲线

- **结构**：主动技能 = 类型标签集合（117 种）+ 施法时间 + 武器限制 + 每级数值表；
  辅助 = 允许的类型 / 排除的类型 + 消耗倍率 + 每级数值（`data/skills.json`）。
- **门控**：448 个辅助里 186 个带 `excluded_types`；最常见的允许组合是
  `Attack+Damage`（67 个）、`Melee`（21 个）、`Spell+Triggerable`（28 个）
  （`support_rules.allowed_type_combinations`）。这比“辅助只能插对应颜色”更有表达力：
  **用标签集合做匹配，而不是硬编码技能白名单**。
- **等级曲线**（主动技能，1→20 级）：
  - 伤害倍率中位 **2.36×**（p25 0.84，p75 3.95）——相当一部分技能 1→20 几乎不涨伤害，
    靠辅助/品质；p9 应保证**每个技能至少一条随等级成长的轴**，否则升级没有反馈。
  - 法力消耗中位 **1.83×**（8 → 18）；角色等级需求中位 12 → 70；属性需求中位 33 → 155。
  - 施法时间 1000ms 最常见（514 个），其次 500/600/800ms——p9 用 3–4 档即可。
- **建议**：p9 用 10–15 个主动技能 × 3–4 个辅助槽，辅助池 20–30 个，标签 8–12 种
  （近战/投射物/法术/范围/持续/召唤/光环/位移/火焰/冰霜/闪电/物理），
  而不是 117 种标签。

### 1.5 稀有度、掉落与货币循环

- **可观测的事实**：装备基底掉落等级分布 1–84，集中在 20–70
  （`data/drops.json.base_drop_level_buckets`）；1083 个可堆叠货币基底，堆叠上限分布为
  1（451 个）、10（436 个）、20（119 个）、100（22 个）、250（10 个）。
- **不可观测**：RePoE 不含稀有度权重、物品掉落权重、交易数据。**不要假装这些是 PoE 数据**；
  `schema.example.json.drop_table` 里的 `1000/180/12/0.4` 已标注 `authored: true`。
- **值得借鉴的循环**：货币不是“钱”，而是**对装备做确定性操作的消耗品**（重铸、升级稀有度、
  定向加词缀）。p9 可以只保留 3–4 种：
  1. 重铸（清空词缀，保留基底/ilvl）
  2. 升稀有度（白→蓝→黄，逐步开放词缀槽）
  3. 定向移除/锁定一条词缀（高价值消耗）
  4. 重掷数值（保留 tier，重掷区间）
- **不建议**：交易市场、汇率、赛季重置。p9 是单机/小队游戏，经济系统只会制造通胀与
  “最优解搬运”，而不是玩法。

## 2. 不适合 p9 的机制

| 机制 | 为什么不适合 | p9 替代 |
| --- | --- | --- |
| 交易 + 通货兑换 | 需要玩家基数与反作弊；会退化成“查价网站” | 只做 crafting 消耗品，不做市场 |
| 赛季/联盟机制 | 需要持续内容产能与迁移设计 | 用“地图词缀/难度包”做可重复内容 |
| 6 条随机词缀 + 123 后缀池 | 单件装备信息过载，目标词缀命中率极低 | 每件 4–6 条，池子 24–40/槽 |
| 5 层稀有度 + 腐化/附魔/催化剂 | 组合维度爆炸，UI 与平衡成本高 | 3–4 层稀有度，1 种强化途径 |
| 1000+ 节点天赋树 | 小团队无法平衡；玩家需要攻略 | 30–50 点的小树，每点都是明确选择 |
| 宝石 20 级 + 品质 + 腐化 + 觉醒 | 单一技能的成长通道太多 | 技能 1–20 级 + 1 条品质轴 |
| 抗性惩罚随章节递增 | 迫使玩家反复换装，节奏割裂 | 固定 cap，靠装备词缀解决 |
| 装备属性需求指数增长 | 后期必须堆属性，压缩 build 空间 | 需求上限 ≈ 等级 × 1.2–1.5 |

另有两个“数值陷阱”值得写进 p9 的平衡守则：

1. **抗性 tier 饱和**：PoE 火抗最后一级只比前一级多 2 点（46-48 vs 42-45），因为 cap=75。
   p9 若 cap 更低，顶层 tier 必须换成别的维度，否则是死词缀。
2. **技能伤害不涨**：PoE 有 25% 的主动技能 1→20 伤害倍率 ≤ 1（p25=0.84）。
   p9 不要模仿这种“靠辅助补”的设计，升级曲线要单调。

## 3. p9 建议参数（起步值）

以下数字是**建议**，不是 PoE 实测；括号内是 PoE 的参考值，便于判断量级。

| 参数 | p9 建议 | PoE 参考 |
| --- | --- | --- |
| 装备槽 | 9 类（双戒指共 10 件：武器/副手/头/胸/手/脚/腰/戒指/项链） | ~10 |
| 每件词缀上限 | 稀有 3 前缀 + 3 后缀；魔法 1+1；普通 0 | 3+3 / 1+1 |
| 每槽词缀族 | 24–40 前缀 + 24–40 后缀 | ring 78/123，body 43/58 |
| 每族 tier 数 | 4–6 | 中位 4，p75 7 |
| tier 等级门槛 | 1 / 12 / 26 / 42 / 60（步长 5–14） | 5–12 |
| tier 权重 | 1000 / 600 / 350 / 200 / 100（顶级 ≈4.4%） | 多为等权，顶级 9–33% |
| 单 tier 数值成长 | 每级 +35–50%（生命 +15 上限/级） | 生命 8 tier 12.7× |
| 掷值方式 | tier 内均匀；不额外做“高 roll”权重 | 均匀 |
| 稀有度权重 | common 1000 / magic 180 / rare 12 / legendary 0.4 | 未公开 |
| ilvl 上限 | 60–80 | 84–100 |
| 抗性 cap / 最大抗 | 75 / +2、+4 两档 | 75 / 多档 |
| 技能槽 / 辅助槽 | 5 / 3 | 多组 6L |
| 主动技能数 | 12–20 | 1010（含变体） |
| 辅助池 | 20–30 | 448 |
| 技能标签 | 8–12 | 117 种类型 |
| 技能等级 | 1–20，伤害 ×2.5–3，法力 ×1.8 | ×2.36 / ×1.83 |
| 技能点 | 30–50 | 100+ |
| 怪物生命曲线 | `L^1.6` | `1.57·L^1.85`（r²=0.88） |
| 怪物伤害曲线 | `L^1.35` | `0.56·L^1.45`（r²=0.87） |
| 怪物护甲曲线 | `L^1.8` | `0.71·L^2.38`（r²=0.90） |
| 基底防御 | `a·ilvl^0.9` | 0.85–0.92 |
| 武器 DPS | `a·ilvl^0.65` | 1h 0.51 / 2h 0.77 |

**为什么顶级 tier 要压到 4% 左右**：p9 的池子只有 PoE 的 1/3，若等权，顶级词缀命中率
20% 起步，10 次重铸就能毕业。`1000/600/350/200/100` 的组合让“接近毕业”常见、
“真正顶级”稀有，同时不引入交易。

**为什么怪物曲线要压**：PoE 的 `L^1.85` 生命 + `L^1.45` 伤害意味着玩家防御必须指数成长；
p9 若等级封顶 60 且装备成长近似线性（防御 `ilvl^0.9`），用 1.6/1.35 才不会后期暴毙或刮痧。

## 4. 与 p9 数据结构的对应

`schema.example.json` 是一份自命名的完整示例，字段与 `data/*.json` 同构，建议 p9 直接采用：

- `slots[]`：槽位 + 可接受基底类别 + 每件前后缀上限（把“3+3”写成数据，不写死在代码里）。
- `base_type`：`id / slot / class / ilvl / drop_level / requirements / defence / tags`。
- `affix_families[]`：`id / kind / stat / slots / exclusive_group / tiers[]`；
  tier 含 `ilvl / stats / slot_weight`。
- `stat_catalog[]`：`key / unit / stack_mode / applies_to / cap`，供 UI 与结算共用。
- `aggregation`：pipeline + worked examples（可直接当单测夹具）。
- `skill` / `support`：技能曲线、标签、门控与消耗倍率。
- `drop_table`：稀有度权重（标注 authored）。

实现顺序建议：`stat_catalog` → `aggregation`（先能算对一个数）→ `base_type` →
`affix_families` + tier 抽选 → `drop_table` → `skill/support`。先做“一件装备从掉落到
面板数字”的闭环，再扩词缀数量。

## 5. 合规与风险

- **不复制**：技能名、装备基底名、词缀名（如“of the Brute”）、unique 名、描述/风味文本、
  图标与模型。`tools/extract.py` 已经完全不读这些字段；产物可用
  `grep -c '"name"\|"description"\|Art/2DItems' data/*.json` 自检为 0。
- **数值的使用边界**：区间数字（如生命 3-9、抗性 6-11）是事实性参数，用于校准；
  p9 上线时应换成自己重算的数值表，并在文档里注明“参考量级”，不要声称是 PoE 数据。
- **原始文件**：只放 `/tmp/poe-data/`，不 commit、不随构建产物发布；`data/` 只含聚合摘要。
  若仓库将来公开，建议把具体掷值也视为内部参考，必要时只保留统计（`_summary.json`）与公式。
- **商标**：不要在 p9 的宣传、UI、代码标识里使用 “Path of Exile”“PoE”“GGG” 或任何
  unique/skill 名；引用时用“某 ARPG 的设计”描述。
- **数据漂移**：快照为 2026-10-19；补丁会改数值与词缀表。重新生成前先比对
  `meta.inputs.*.sha256`，否则文档里的具体数字会过期。
- **语义推断**：spawn weight 的“有序首个匹配”来自 RePoE 文档；tier 由 `required_level`
  排序推导，PoE 内部还有我们看不到的池规则，因此统计是**近似**，用于设计判断足够，
  不要当作精确复刻。

## 6. 一句话给 p9 的实现者

> 抄它的**层级**（基底 → 词缀族 → tier → 权重 → 聚合），不要抄它的**数量**
> （123 个后缀、6 条词缀、117 个标签、1000 点天赋）；把“毕业”从“抽中 1/123”变成
> “在 30 个可理解的选项里做 3 次正确取舍”。
