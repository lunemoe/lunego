# LG008 框架与 kit 的领域边界

## 规则

- `packages/core`、`packages/host`、`packages/testkit` 等运行时包不得出现 AI、任务、战斗、物品、掉落、技能等具体玩法/领域语义；框架只提供机制。
- `kits/*` 可以提供**通用机制名**（如 ai/quest/status/items/encounter/zone），但不得包含具体游戏内容、数值表、剧情/物品数据，也不得 import `features/*`、`games/*` 或 `content/*`。
- 所有框架包不得 import 游戏代码或游戏内容；内容数据只能由游戏的 feature/content 提供。

## 原因

框架必须能被任意游戏复用；kit 是“被多个游戏需要的通用机制”，不是第一款游戏的内容仓库。玩法数据进入 kit 后，第二个游戏会被迫继承第一款游戏的假设。

## 强制手段

- dependency-cruiser `packages-no-game-code`、`kits-no-game-code`、`kits-direction`。
- `lunego check` 对游戏目录内的 kits 做同样的路径/依赖检查。
- “具体玩法名词/内容数值”无法完全机器判断，**需人工审查**；测试夹具可以使用玩法词，但不得被核心/kit 运行时源码 import。

## 修法

- 机制通用化后晋升到 kit；具体内容、数值、剧情和游戏导入留在游戏的 `features/*/content` 或 `features/*/logic`。
- 框架运行时的领域语义应改名为中性的机制名，或下沉到游戏。
