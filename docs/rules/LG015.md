# LG015 新 feature 必须有 README 契约和测试；修改框架必须附变更记录

## 规则

每个 `features/<name>` 必须有 README（意图、公共接口、不变量、依赖）和测试；框架改动必须附带 changeset 与规则/文档更新。

## 原因

feature 的契约和测试就是 AI 的上下文边界；没有契约的模块会被误用。

## 强制手段

- 提交前本地 `pnpm check` 运行 build / typecheck / lint / depcruise / test / gen:check / Playwright 冒烟；本项目不使用 GitHub CI。
- changesets 管理框架变更记录。
- 提交/推送由本地受信 hook 执行 `pnpm verify` 对应的隔离验证，绑定实际 Git tree。旧契约、报告完整性、故障敏感度与玩家输入验收见 LG017；普通实现任务不能通过修改测试或门禁同时掩盖回归。
- `lunego check` 校验 feature README、测试、生成物、schema.lock 与依赖方向；`docs/generated/` 项目地图仍属后续。

## 修法

新建 feature 时同时写 README 与场景测试；修改框架时运行 `pnpm changeset`。
