# LG005 写权限归属（writers）

## 规则

组件、Tag、Model 默认只有定义它的 feature 能写。其他 feature 需要写入时，有两种显式声明：

- 在状态定义处声明 `writers: [...]`，列举允许写入的 feature 名。
- 在写入方 feature 上声明 `writes: [StateDef, ...]`，从 feature 角度声明它要写这些（别人拥有的）状态。

## 原因

任何一个字段的写入者都可以被列举；跨 feature 直接改状态是腐坏的起点。

## 强制手段

- 注册期：`WorldCatalog` 先校验 feature 的 `writes` 是否指向已注册的状态（否则注册错误），再把 feature 名并入该 catalog 的 `featureWrites`；随后校验每个 System / Handler 的 `writes` 是否在 owner + `writers` + `featureWrites` 内，否则抛 `LG005`。
- `writers` 中的 feature 名必须存在。世界里凡声明了 `writers` 的 feature 都必须被注册（单 feature 测试也要把参与写权限契约的 features 一并传入 World）；这是注册期校验写权限归属的必要条件，不是可放宽的便利条件。

## 修法

优先让 owner feature 提供 Command 或请求事件；确实需要多方写入时显式加 `writers`，或在写入方 feature 上声明 `writes`。
