# LG010 持久化 schema 变更必须升版本并提供迁移

## 规则

`persist` 数据的 schema 变化必须提升 `schemaVersion` 并提供迁移；存档读取必须校验版本。

## 原因

旧存档不能静默读进新结构；版本检查把数据损坏变成可诊断错误。

## 强制手段

- 快照包含 `formatVersion` 与 `schemaVersion`；`World.fromSnapshot` 不匹配时抛 `LG010`。
- 组件/模型必须存在于当前 scope，未知或缺失的持久化字段会报错。
- `schema.lock.json` 与迁移函数属于后续 `lunego gen/check` 批次；当前由版本校验与审查兜底。

## 修法

提升版本、写迁移、补读档透明测试。

## 存档透明性（本轮补充）

快照必须记录 `dt`、内容哈希与待执行命令；`World.fromSnapshot` 默认使用快照的 `dt`，显式分歧会抛错。世界档与档案档用 `World.fromSnapshots` 显式合并，二者必须同 tick、同实体表。`previousEvents` 是“事件不进存档”的唯一例外，用于跨 tick 的 `{ prev: true }` 监听。`persist: null` 的状态开发模式首次快照时给出 `snapshot-ephemeral` 告警。
