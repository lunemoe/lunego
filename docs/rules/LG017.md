# LG017 技术质量与回归门禁

## 规则

- 运行时入口不得为空，或忽略全部输入而恒定返回成功。实现必须连接到调用路径。
- 不复制较大实现，不用无行为转发函数规避文件职责与行数约束；保留直接导出别名与真正的边界适配。
- 不允许空测试、skip/only/todo/条件跳过、预期失败；已保护的测试身份不得消失。
- 实现和测试一起变更时，旧契约必须在新实现上通过。旧测试、夹具、快照与发现配置从受信 Git tree 提取。
- 玩家验收只能通过真实输入/UI 操作；调试接口只允许读状态。命令无效、界面无反馈、进度无法继续应直接失败。
- 关键契约必须能检测既定故障集。未注入、未收集、编译错误和不相关的失败不算通过故障验收。
- 提交和推送使用精确 tree 的验证证据；修改检查规则与升级契约基线须独立审核，不得由普通实现任务自行放宽。

## 强制手段

LG013 空实现检查、`tools/quality` AST/模块图检查、隔离验证、旧契约复跑、故障注入、只读玩家验收、本地签名证据和 Git hooks。完整命令与信任流程见 [`tools/quality/README.md`](../../tools/quality/README.md)。无 GitHub CI。

## 边界

门禁检查客观行为和已定义的架构约束，主观趣味及任意新增算法的正确性仍需相应验收。拥有同等文件系统与 Git 管理权限的恶意操作不在本地门禁的安全保证内。
