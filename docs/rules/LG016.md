# LG016 框架是唯一通道

## 规则

游戏代码（`games/**`、`features/**`、`kits/**`、`templates/**` 的源码、内容与测试）只能：

- import `@lunego/*` 包，或自己的相对模块 / `schema.ts` / `content`；
- 使用框架导出的能力访问浏览器、平台、渲染、音频、存储、输入与时间。
- UI 的 Solid 原语（`createSignal/createMemo/createEffect/createRoot/onCleanup/html/createComponent`）只能从 `@lunego/ui` 取，不能直接 import `solid-js`。

禁止：

- 直接 import `pixi.js`、`solid-js`、`node:*`、裸平台包或 `@lunego/core/internal`；
- 直接使用 `document`、`window`、`navigator`、`localStorage`、`sessionStorage`、`AudioContext`、`HTMLAudioElement`、`Image`、`fetch`、`WebSocket`、`requestAnimationFrame`、`performance` 等平台全局；
- 在游戏 view 里自建 `worldToScreen` / `screenToWorld` / `cameraX` / `cameraY` / `bodyCenter` / `anchorOf`，或猜测精灵宽高；应使用 `renderer.viewport`、`renderSystem.anchorOf`、`PixiAdapter.measure`；
- 在 `defineRenderBinding` 的 create/update 中写死 width/height 数字；尺寸必须来自 manifest、纹理/帧表、DisplaySpec 或 measure。

## 原因

如果每个游戏都自己接 Pixi/Solid/WebAudio/DOM/时钟，框架的坐标、存档、回放、确定性、资源生命周期就无法统一；AI 也会在不同游戏里复制不同实现。框架缺能力时，先补框架包/API，再写游戏。

## 强制手段

- `@lunego/eslint-plugin` 的 `lg016`，按游戏源码分区启用；`@lunego/debug-entry` 只允许只读调试暴露。
- dependency-cruiser：游戏路径只允许 `@lunego/*`/相对模块，禁止平台包、Node 内置与 core internal。
- `lunego check` 在游戏目录运行框架导出的 ESLint flat config（含 LG016）与 dependency-cruiser，报 `LG016 file:line`。
- 根 `pnpm check` 对模板/游戏跑同一规则；框架包自身可用平台 API。
- 审查兜底：无法机器识别的“自建等价实现”按本规则拒绝。

## 修法

1. 先找 `@lunego/*` 中对应的终局 API；没有就在框架补包/API、测试和 README/changeset。
2. 用 `renderer.viewport` 做坐标/指针；用 `renderSystem.anchorOf(...,{binding|layer})`/`measure` 做锚点/尺寸；用 `createViewLoop` 做 RAF/模拟时间；用 `createBrowserSaveStore` 做存档；用 `@lunego/ui` 的受限 Solid 原语与 `EffectOverlay` 做 DOM UI/特效；用 `@lunego/audio` 的 bus/`MusicController` 做音频。
3. 删除本地 camera/viewport/FPS/资源加载器等重复实现。
