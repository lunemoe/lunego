# p9 需求说明

本文件记录用户对第一款游戏 p9 的完整产品要求。p9 就是本仓库的 `templates/game`，与框架一起迭代；先完善框架，再完善同一个游戏。这里描述最终目标，不代表所有条目已经实现。

## 定位

- 真正的 Hero Siege 式俯视角像素 ARPG；不是幸存者（survivor-like），也不是"三选一"式的 roguelite 循环。
- 核心是"有地图、有 BD（build）"：玩家在地图上推进，成长来自装备、技能与点数分配。
- 自动战斗只能作为可选辅助，不能成为主玩法。

## 核心循环

1. 进入地图（房间/关卡），探索并清理敌人。
2. 掉落装备与材料，鉴定词缀，替换更好的装备。
3. 分配技能点与被动，形成自己的 BD。
4. 打精英与 Boss，进入下一张地图或下一个难度。
5. 循环并积累：等级、装备、技能、金币、任务进度。

必须包含：地图探索、刷怪、装备与词缀、技能与技能树/被动、Boss、成长与掉落。

## 美术规格

| 类型 | 尺寸（单帧） |
|---|---|
| 普通角色 | 64×64 |
| 大型怪 | 96×96 或 128×128 |
| Boss | 128×128 起，可到 160×160 |
| 地面 Tile | 32×32 或 64×64 |

- 像素风，透明背景，统一调色板，整数缩放、最近邻采样。

## 内容要求

- 地图：多个 biome，风格与敌人组不同。
- 城镇/安全区：NPC、商店、任务。
- 战斗：多种敌人，Boss 有多个阶段。
- 角色成长：2 个以上职业，各自的技能树与被动。
- 装备体系：槽位、属性、词缀、稀有度、掉落表。
- 消耗品：药水等。
- 表现：音乐与音效、完整 UI（背包、装备、技能、状态、小地图等）。

## 数据参考

- PoE 数据只作为"结构与数值形状"的参考（槽位划分、词缀族与 tier 的形态、稀有度层级）。
- 名称、文本、美术、具体数值全部自创；不复制任何受版权保护的内容。

## 技术铁律

- 游戏代码只能 import `@lunego/*` 与自己的 `schema.ts` / `content`；LG016 必须零违规。
- 禁止直接使用 `pixi.js`、`solid-js`、DOM 全局、`WebAudio`、`requestAnimationFrame`、`performance`、`localStorage`、Node 内置。
- 坐标、锚点、时间、资源加载、输入、存储、UI 全部走框架提供的 API。
- 先完善框架，再写游戏；框架缺能力时先在框架补包/API。

## 验收

- 确定性与回放：相同初始状态与命令序列得到相同哈希。
- 存档/读档透明：连续运行与中途存读档结果一致。
- 坐标/锚点矩阵：不同 zoom、相机位置、角色尺寸下特效与 UI 对齐。
- LG016 零违规，`lunego check` 通过。
- Playwright 覆盖关键玩法路径。
- 不留临时实现、占位代码、TODO 或注释掉的代码。
